# Current backend matching vs `match_skills(method="hybrid")`

Generated by `nlp/experiments/compare_with_current.py` on 2026-10-15 (run time 1.4 s; catalogue skills use the cached skill embeddings, so matching needs no model load once `nlp/resources/skill_embeddings.npy` exists).

**Setup.** 200 synthetic students (random sample, seed 42, from `data/output/`) assessed against all 6 roles in `database/seed_job_role_skills.sql`: 1200 assessments, 30,400 required-skill rows. *Current* is the logic in `backend/routers/assessments.py` today (same `skill_id` -> strong; one name contains the other -> developing; else gap), reimplemented in the script. *Hybrid* is `nlp.match_skills` with MATCH 0.60, RELATED 0.50. Both use the weighted readiness score of `assessments.py`.
